# Запуск тестов

Установите зависимости приложения и тестов:

```bash
python -m pip install -r requirements.txt -r requirements-dev.txt
```

По умолчанию тесты используют `FakeSession` в памяти и не требуют сервера БД:

```bash
python -m pytest -q
```

Для проверки SQL и блокировок запустите тот же набор на настоящем PostgreSQL.
Задайте URL отдельной тестовой БД; пользователь должен иметь право `CREATE`
на эту БД:

```bash
TEST_DATABASE_URL='postgresql+psycopg://isudo:isudo@localhost:5432/isudo_test' \
  python -m pytest -q
```

При явном `TEST_DATABASE_URL` ошибка подключения завершает тесты с ошибкой,
без перехода на `FakeSession`. Обычный `DATABASE_URL` приложения не включает
этот режим.

Каждый запуск создаёт уникальную схему `pytest_<uuid>` и использует её для
таблиц и типов enum через `search_path`. В конце удаляется только эта схема;
существующие схемы, включая `public`, не изменяются. Каждый тест работает во
внешней транзакции с savepoint: вызовы `commit()` и `rollback()` приложения
не мешают откату данных после теста. Фикстура `postgres_engine` позволяет
тестам блокировок открыть дополнительные соединения в той же схеме; такие
тесты пропускаются при запуске без PostgreSQL.
